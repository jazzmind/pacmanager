# Product and adoption design
## Promise
Create something useful with a familiar AI client; share it with colleagues; hand engineering a conventional, understandable application when it outgrows the environment. Graduation means reduced rework, not automatic production certification.

## First useful journey
A team creates a knowledge-backed decision log from synthetic or explicitly uploaded documents. Colleagues annotate decisions and inspect citations. A small form/dashboard evolves around the same data. A claims simulator can be bound later, without changing application logic.

## Three zones
Studio: private branches, synthetic data and disposable previews.
Shared: deployed internal software with owners, backups, patching, quotas and revocable permissions. This is operational production even if low criticality.
Graduated: ownership/SLOs, deployment and data migrate to enterprise operations; runtime may remain in PAC Manager if requirements fit.

## Independence from IT
IT approves templates, data classes, resource budgets and capability catalogs ahead of time. Users publish within those envelopes. New enterprise connections and risk exceptions require approval. Automated checks reduce tickets; they do not replace business accountability.

## Platform users and plugin value
Chat/coding-agent users gain a durable publish target through an authoring adapter.
Existing workflow/agent platforms gain policy-bound connectors and a common artifact catalog.
Sandbox providers gain persistent artifact identity and lifecycle integration.
Backstage users gain source and evidence on graduation.
Third-party runtime artifacts retain their native source/export formats; the PAC wrapper must not promise conversion of arbitrary workflow graphs into ordinary application code.

## Success measures
Measure time to first shared useful artifact, ticket-free publication rate, repeat collaborators, restore success, adoption beyond the author and engineer time to run an exported artifact.
Recruiting measures: external repeat contributors, accepted fixes, maintainer response time, candidate references to project work. Stars and social impressions are secondary.
Target hypotheses: useful artifact in 30 minutes and an engineer running its export in one hour. Validate, do not advertise as achieved.

## Non-goals
Not a new IDE, foundation model, low-code language, hypervisor or universal enterprise digital twin. No private customer data in public examples; no commercial feature gating.
